# 2. 第一个因果实验

我们先研究一个足够小、能逐行算清楚的网络。问题是：**如果两个节点都准确记录输入，删除它们是否会有相同后果？**

本章无需安装软件。先操作下面的实验；愿意运行 Python 时，再按[环境准备](../guide/setup.md)安装。

<CausalPlayground />

## 2.1 先观察，不改动

输入 $x$ 只能取 0 或 1。网络中有两个中间节点：$h_1=x$、$h_2=x$。我们称它们在一次运行中的数值为**激活**（activation）。输出分数是 $s=2h_1-1$；分数大于零时预测类别 1，否则预测类别 0。

| 输入 | $h_1$ | $h_2$ | 分数 | 预测类别 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | −1 | 0 |
| 1 | 1 | 1 | 1 | 1 |

两个节点都能告诉我们输入是什么。只凭这张表，无法知道哪个节点影响了输出；还需要观察连接权重，或直接干预计算。

## 2.2 消融：把节点置零

消融（ablation）是人为去除或替换一部分计算。最简单的做法是把某个激活置零。

当 $x=1$ 时，把 $h_1$ 置零，得到 $s=-1$；把 $h_2$ 置零，仍有 $s=1$。这与公式的预测一致，因为 $h_2$ 的输出权重是零。

注意 $x=0$ 的情形：$h_1$ 原本就是零，置零当然没有变化。这不能证明 $h_1$ 在整个网络中没有作用，只能说明这次干预没有改变它的值。我们应该在一组输入上做实验。

以下纯 Python 代码直接表达这次干预，不需要 PyTorch：

```python
def forward(x, replace=None):
    h = [float(x), float(x)]
    if replace is not None:
        node, value = replace
        h[node] = value
    score = 2 * h[0] - 1
    return h, score

print(forward(1))                  # ([1.0, 1.0], 1.0)
print(forward(1, replace=(0, 0)))  # ([0, 1.0], -1)
print(forward(1, replace=(1, 0)))  # ([1.0, 0], 1.0)
```

Python 从零开始编号，所以 `node=0` 对应数学里的 $h_1$。

## 2.3 修补：把另一轮运行的值搬过来

现在把 $x_c=1$ 称为参考输入（clean），把 $x_r=0$ 称为对照输入（corrupted）。这些名称只描述实验角色；$0$ 本身并不是错误数据。

我们先运行参考输入，保存 $h_1=1$。再运行对照输入，但在中途把它的 $h_1$ 替换为保存的值。于是对照运行从 $s=-1$ 变成 $s=1$。

这就是**激活修补**（activation patching）的基本操作：从一次运行取出激活，放入另一轮运行的指定位置，然后继续计算。

```python
clean_h, clean_score = forward(1)
_, corrupted_score = forward(0)
_, patched_score = forward(0, replace=(0, clean_h[0]))
print(clean_score, corrupted_score, patched_score)  # 1.0 -1.0 1.0
```

只替换 $h_2$ 就不会恢复输出。这一差异是计算结构造成的，不是两个节点携带信息量的差异。

## 2.4 “恢复了多少”怎样计算

一种常见的归一化指标是：

$$
R=\frac{s_{\mathrm{patched}}-s_{\mathrm{corrupted}}}
{s_{\mathrm{clean}}-s_{\mathrm{corrupted}}}.
$$

在我们的例子里，替换 $h_1$ 得到 $R=(1-(-1))/(1-(-1))=1$；替换 $h_2$ 得到 $R=0$。它们分别表示恢复了全部分数差和没有恢复分数差。

这个公式不是概率。别的网络可能得到负值或大于 1 的值。当分母等于零或非常小时，它甚至没有稳定意义。完整实验程序会拒绝把接近零的分母当作有效的恢复率。

## 2.5 把两条路径都接到输出会怎样

考虑新模型 $y=\max(h_1,h_2)$，仍有 $h_1=h_2=x$。对于 $x=1$，分别删除任意一个节点都不改变输出，但同时删除两个就会改变输出。这里存在冗余路径。

这个例子足以推翻“单独消融没有效果，所以组件没有用”这一推理。第七章还会比较 AND 与 OR 型结构，理解为什么修补和消融会给出不同图景。

::: warning 这个方法会怎样误导我们
我们手工规定了网络结构，因而可以知道完整答案。这是方法演示，不是发现了真实语言模型的机制。实际模型的中间状态更复杂，置零可能远离正常状态，其他组件也可能补偿被删除的功能。
:::

## 小结

观察问的是“这个值与什么一起变化”，干预问的是“主动改变这个值会发生什么”。激活修补还多问一步：把参考运行中的内部状态移入对照运行，能恢复多少目标行为？答案始终依赖输入、替换位置和测量指标。

## 练习

1. **基础**：在交互实验中令 $x=0$，分别消融两个节点。解释为什么两次都没有变化。
2. **基础**：把代码的输出改成 `2 * h[1] - 1`。先预测，再运行。
3. **进阶**：对 $y=\max(h_1,h_2)$ 列出两个单独消融和联合消融的结果。这给“必要组件”一词带来什么限制？
